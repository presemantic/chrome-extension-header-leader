# Header Leader - HTTP Header Editor

## Purpose

This project is a dependency-free Chrome Manifest V3 extension for managing named profiles of outgoing HTTP request-header modifications. The interface is English-only and follows a restrained editorial style with warm neutral colors, dark typography, thin rules, and no badges.

## Structure

- `manifest.json` declares the Chrome extension, permissions, background worker, toolbar popup, and icons.
- `service-worker.js` initializes local state and reconciles selected profiles through `chrome.declarativeNetRequest`, atomically removing every stale dynamic rule before installing the current generated rule.
- `core.js` contains state normalization, validation, and dynamic-rule construction shared by the UI, worker, and tests.
- `manager.html`, `manager.css`, and `manager.js` implement the maximum-size 800x600, two-column toolbar popup with a 300px profile column on the left and the wider remaining space dedicated to header controls on the right. Clicking a profile row or its name selects it for header editing; hovering a profile inverts the row to a black background with light text, icons, and switch treatment, while selected rows receive no persistent background. A separate pencil button to the left enters inline name-edit mode; activation remains visible through the row switch and left-edge marker, and each row has a compact immediate-delete action. The profile and header headings each provide independent session-local, multi-level UNDO stacks: profile undo restores position, activation, and editor selection, while header undo restores the original profile and list index even across repeated deletions. Both headings use the same compact square `+` action. The profile list and header table each reserve permanent width for matching always-visible custom scrollbars whose thumbs support wheel synchronization, track clicks, and pointer dragging, so overflow never shifts either list. The header table labels only the `NAME` and `VALUE` columns while retaining unlabeled switch and operation controls, and uses a left-side drag handle with insertion feedback to persist order without changing scroll position; the handle supports keyboard up/down movement.
- `icons/` contains extension artwork, and `tests/` contains dependency-free static logic tests.
- `LICENSE` contains the MIT license, `PRIVACY.md` is the public Chrome Web Store privacy policy, and `STORE_LISTING.md` contains the canonical English listing, permission justifications, privacy disclosures, distribution settings, and asset paths.
- `assets/render-screenshots.mjs` renders five 1280x800 Chrome Web Store screenshots from the real popup HTML/CSS and fictional header data. `assets/` also contains the final `small.png` and `merquee.png` promotional tiles; generated intermediates remain ignored under `assets/generated/`.

## Constraints

Keep the extension dependency-free and compatible with Chrome Manifest V3. Store profile data only in `chrome.storage.local`; profile names are limited to 32 characters, while the interface must not impose a count limit on profiles or header rows. Apply all active profiles and only their individually enabled header rows to outgoing HTTP and HTTPS requests using a single dynamic rule that explicitly includes `main_frame` and the remaining Chrome resource types so the initial top-level navigation receives the same headers as subresources. For duplicate case-insensitive header names, later `set` or `remove` rows win; consecutive `append` rows are combined in order. Use native DNR append for Chrome's supported request-header allowlist, and emulate custom-header append with a comma-separated `set` value because Chrome rejects native append for those names. Reconcile the dynamic rule on install, startup, storage changes, and every popup initialization so persisted rules from older unpacked-extension reloads cannot remain active. Turning off the global switch must visually switch off and disable all profile-row switches while preserving their active-profile selection, then restore that exact selection when the global switch is enabled again. Do not use remote code, analytics, network calls, or badge state.

Verification must remain static: JSON parsing, JavaScript syntax checks, focused core tests, archive inspection, and diff review. Do not launch Chrome, load the unpacked extension, or make HTTP requests unless the user explicitly asks for runtime verification.
